# `audit-event` — the audit envelope

**Published by:** A13. Consumed by every agent that writes, reads or refuses
anything.
**Requirements:** REQ-AUD-01 … REQ-AUD-06, REQ-AUD-13, REQ-RBA-07, REQ-RBA-08,
REQ-ENT-02, REQ-ENT-04, REQ-API-08, REQ-GRD-13, REQ-TIM-03.
**Consumed by:** A03, A04, A05, A07, A09, A10, A11, A12, A15, A16, A23.

A domain never writes to `audit_events` directly. It emits an `AuditEvent`
through `packages/audit`, which redacts (§4), chains (§5) and inserts. One
writer is what makes the hash chain and the redaction rules provable.

---

## 1. The envelope, field by field (REQ-AUD-04)

| Field | Type | Null | Meaning |
|-------|------|------|---------|
| `id` | `uuid` | no | Event identity. Generated by the emitter. |
| `occurredAt` | `timestamptz` | no | UTC instant the action completed, or was refused. |
| `kind` | enum | no | `write` \| `read` \| `view` \| `auth` \| `policy` \| `system` (§3). |
| `action` | event name | no | `<domain>.<resource>.<action>` (§2). |
| `result` | enum | no | `success` \| `denied` \| `failed` \| `expired`. |
| `tenant` | `TenantRef` | yes | Null only for a global-tier action outside any tenant. |
| `actor` | `ActorRef` | no | `session.actor`. Under impersonation this is the **subject**. |
| `onBehalfOf` | `ActorRef` | yes | `session.impersonation.impersonatedBy` — the operator doing the acting (REQ-RBA-07). |
| `impersonationId` | `uuid` | yes | Correlates enter, every action inside, and exit. |
| `permission` | permission string | yes | The permission that was demanded. Null where the route is authenticated-only. |
| `target` | `{ kind, id, label }` | yes | What was acted on. `kind` is `<domain>.<resource>`. Null for a login. |
| `diff` | `{ before, after }` | yes | Writes only, redacted (§4). Null for reads and auth events. |
| `comment` | `text` | yes | The caller's reason, copied from the entity envelope (`entity-base.md` §1). |
| `settingsScope` | `"personal" \| "tenant" \| "global" \| null` | The scope a settings change was made at (REQ-SET-09). `null` for non-settings events. Without it, "show me every global change" is not a query. |
| `correlationId` | `uuid` | no | Joins to the problem body, the log record and the console frame. |
| `ip` | `inet` | no | Source IP, server-derived. |
| `userAgent` | `text` | no | Truncated at 512 chars. |
| `source` | enum | no | `web` \| `api` \| `system` \| `collector`. Where the request entered. |
| `sampling` | object | yes | Read/view aggregation state (§3). Null for everything else. |
| `chain` | object | no | Hash-chain fields (§5). Written by the emitter, never by a caller. |

```ts
// packages/audit/contract.declaration.ts
import { z } from "zod";
import { ActorRefSchema, TenantRefSchema } from "@app/contracts/identity";
import { PermissionStringSchema } from "@app/contracts/rbac";

export const AuditEventSchema = z.object({
  id: z.string().uuid(),
  occurredAt: z.string().datetime({ offset: false }),
  kind: z.enum(["write", "read", "view", "auth", "policy", "system"]),
  action: z.string().regex(/^[a-z][a-z0-9-]*\.[a-z][a-z0-9-]*\.[a-z][a-z0-9-]*$/),
  result: z.enum(["success", "denied", "failed", "expired"]),
  tenant: TenantRefSchema.nullable(),
  actor: ActorRefSchema,
  onBehalfOf: ActorRefSchema.nullable(),
  impersonationId: z.string().uuid().nullable(),
  permission: PermissionStringSchema.nullable(),
  target: z
    .object({ kind: z.string(), id: z.string(), label: z.string().max(200) })
    .nullable(),
  diff: z
    .object({ before: z.record(z.unknown()), after: z.record(z.unknown()) })
    .nullable(),
  comment: z.string().max(2000).nullable(),
  /**
   * The settings scope a change was made at, when the event is a settings
   * change (REQ-SET-09). null for every other event. Added as an optional
   * field by additive CCR from A05: the envelope is `.strict()`, so without it
   * no settings panel can record its scope, and a filter for "every global
   * change last week" is impossible.
   *
   * Rejected alternatives, both of which look cheaper and are worse:
   * encoding the scope inside `target.id` turns a column filter into a prefix
   * match; emitting a correlated second event doubles the trail and adds a
   * pairing that can break.
   */
  settingsScope: z.enum(["personal", "tenant", "global"]).nullable(),
  correlationId: z.string().uuid(),
  ip: z.string().ip(),
  userAgent: z.string().max(512),
  source: z.enum(["web", "api", "system", "collector"]),
  sampling: z
    .object({
      sampled: z.boolean(),
      aggregatedCount: z.number().int().positive(),
      windowStart: z.string().datetime({ offset: false }),
      windowEnd: z.string().datetime({ offset: false }),
    })
    .nullable(),
  chain: z.object({
    seq: z.number().int().positive(),
    prevHash: z.string().regex(/^[0-9a-f]{64}$/),
    hash: z.string().regex(/^[0-9a-f]{64}$/),
  }),
}).strict();

export type AuditEvent = z.infer<typeof AuditEventSchema>;
```

`occurredAt`, `windowStart` and `windowEnd` are UTC `timestamptz` in storage and
RFC 3339 `Z` on the wire. They are rendered only by `packages/contracts/time`,
`Europe/Stockholm` and `YYYY-MM-DD HH:mm:ss` by default (REQ-TIM-03,
REQ-TIM-04). The audit viewer shows seconds; an audit trail without seconds is
not a trail (REQ-TIM-02).

Impersonation mapping is fixed by `contracts/types/identity.md` §6 and is not
restated differently here: `actor` is the subject, `onBehalfOf` is the operator.

## 2. The event-name taxonomy (REQ-AUD-01)

The event name is a permission-shaped string: `<domain>.<resource>.<action>`,
same grammar as `contracts/types/rbac.md` §1. It is usually the permission that
gated the action, which makes "what did this role actually do" a single-column
query. Where no permission gates it — a failed login — the name still follows
the grammar.

| Event | Kind | Emitted when |
|-------|------|--------------|
| `<domain>.<resource>.create` | write | A row is inserted. `diff.before` is `{}`. |
| `<domain>.<resource>.update` | write | A row changes. Both sides of the diff present. |
| `<domain>.<resource>.delete` | write | Soft delete (REQ-ENT-02). |
| `<domain>.<resource>.restore` | write | `deleted_at` cleared. |
| `<domain>.<resource>.purge` | write | Hard delete under `global.record.purge`. |
| `<domain>.<resource>.read` | read | Detail read, sampled per §3. |
| `<domain>.<resource>.list` | read | List read, aggregated per §3. |
| `<domain>.<resource>.export` | write | A file was produced. Carries row count, applied filters, column set (REQ-GRD-13). |
| `auth.session.login` | auth | Session minted. `diff` null, `target` is the session. |
| `auth.session.logout` | auth | Explicit logout. |
| `auth.session.expire` | auth | TTL or idle expiry, `result: "expired"`. |
| `auth.session.revoke` | auth | Revoked by self, tenant admin or global tier. |
| `auth.credential.failure` | auth | Wrong password, TOTP, or assertion. `result: "failed"`. Never records the attempted secret. |
| `auth.mfa.enrol` | auth | Factor enrolled. Recovery codes generated in the same request (REQ-AUT-06). |
| `auth.mfa.reset` | auth | An operator reset another user's factor. |
| `auth.recovery-code.consume` | auth | A single-use code was spent. |
| `auth.policy.write` | policy | Tenant auth policy changed, with diff. |
| `global.auth-policy.mfa-disable` | policy | MFA turned off for a tenant: typed confirmation, before/after (REQ-AUT-05). |
| `rbac.role.write` | policy | Role created or changed. Diff is added/removed permissions (REQ-RBA-08). |
| `rbac.role.assign` | policy | Role granted or revoked for a user. |
| `tenancy.tenant.write` | policy | Tenant profile changed. |
| `global.tenant.create` / `.suspend` / `.archive` | policy | Tenant lifecycle. |
| `global.impersonation.enter` | auth | Entry. Carries `reason`, `expiresAt`, `impersonationId` (REQ-RBA-07). |
| `global.impersonation.exit` | auth | Exit — explicit, expiry (`result: "expired"`) or session revocation. A missing exit is a defect. |
| `api.key.mint` | write | Key minted. Records prefix, scopes, expiry. Never the material (REQ-API-06). |
| `api.key.first-use` | write | First successful authentication with the key (REQ-API-08). |
| `api.key.rotate` | write | Rotation: old prefix and new prefix. |
| `api.key.revoke` | write | Immediate revocation. |
| `api.key.expire` | system | Expiry observed by the sweeper. |
| `mail.message.send` | system | Outbox delivery result per message (REQ-MAIL-04). |
| `collector.agent.enrol` / `.revoke` | write | Agent lifecycle (REQ-OBS-04). |
| `audit.event.export` | write | The audit trail itself was exported (REQ-AUD-13). |
| `audit.chain.verify` | system | Verify job result: `success` or `failed` with the first bad `seq`. |
| `security.rate-limit.trip` | system | A rate limit or lockout tripped (REQ-SEC-11). |

## 3. READ and VIEW, with sampling and aggregation (REQ-AUD-02)

Successful reads are audited. A full trail of every list render is unaffordable
and, worse, dishonest — nobody reads a table with 40 million rows in it, so it
would exist without being read.

| Kind | Meaning | Policy |
|------|---------|--------|
| `read` | A detail read of one identified resource. | Always recorded, never sampled. This is the one that matters in an investigation: "who opened this customer's record". |
| `view` | A list, grid page or search result render. | Aggregated: one event per `(actor, tenant, target.kind, action, query fingerprint)` per window (default 300 s). |

Aggregation rules:

- The first view in a window writes the event with `sampling.aggregatedCount: 1`.
  Subsequent identical views inside the window increment the count on that row.
  This is the single exception to append-only (§6): an `UPDATE` of two counter
  fields, performed by the audit writer's privileged path and never by the app
  role. The chain hash does not change, because those fields are not hashed
  (§5).
- The query fingerprint is a SHA-256 of the canonicalised `PageParams`
  (`contracts/types/pagination.md` §2), so "same filter, same page" collapses
  and "different filter" does not.
- `sampling.windowStart` / `windowEnd` bound the aggregate. A window never
  spans a tenant, an actor or an impersonation session.
- Denied reads are **never** aggregated. `result: "denied"` is always one row.
- `AUDIT_VIEW_WINDOW_SECONDS` is A13's env var. Setting it to `0` disables
  aggregation and records every view — supported, expensive, and the default is
  300.

REQ-TST-08 names read-audit emission as one of the three easily-faked
behaviours: A23 tests that a detail read writes exactly one row and that ten
identical list renders write one row with `aggregatedCount: 10`.

## 4. The redaction contract (REQ-AUD-05)

Redaction happens in the emitter, before the row exists. Not at render, not at
export, not in the console — those all read an already-clean row.

- A domain declares its sensitive fields in its contract declaration:
  `redact: [{ path: "credentials.secret", mode: "drop" }, { path: "user.email", mode: "hash" }]`.
  A02 assembles the registry; A13 applies it. Registry, never a shared list.
- Modes: `drop` removes the key entirely, `mask` keeps a type-shaped
  placeholder (`"****"`, `0`), `hash` stores a salted SHA-256 so two events can
  be correlated without revealing the value.
- The default for an undeclared field in a table that carries any declared
  sensitive field is `drop`. An unknown field is not assumed safe.
- Never in a diff in any mode, regardless of declaration: password hashes,
  TOTP seeds, recovery codes, API key material, OIDC client secrets, SMTP
  credentials, VAPID private keys, session cookies, envelope-encrypted
  ciphertext and its DEK (REQ-SEC-06, REQ-SEC-07).
- The diff records **that** a sensitive field changed: `{ before: { secret:
  "[redacted]" }, after: { secret: "[redacted:changed]" } }`. The audit answer
  "the seed was rotated" is preserved; the seed is not.
- An event whose `diff` fails the redaction schema is not written. It is
  replaced by the same event with `diff: null`, `result` unchanged, and a
  `system` event `audit.redaction.failure` naming the domain and the path. A
  dropped diff is a bug to fix; a leaked seed is an incident.

## 5. Hash-chain fields (REQ-AUD-06)

One chain per tenant, plus one for `tenant: null` global-tier events.

```
hash = sha256(
  prevHash || id || occurredAt || tenantId || actorId || action || result ||
  targetKind || targetId || canonicalJson(diff) || correlationId || seq
)
```

| Field | Rule |
|-------|------|
| `chain.seq` | Per-chain, gapless, starts at 1. Allocated inside the insert transaction. |
| `chain.prevHash` | The previous row's `hash`. Genesis is 64 zeros. |
| `chain.hash` | As above, lowercase hex. |
| `audit_chain` | Holds the current head per chain: `(tenant_id, seq, hash)`. Append-only, entity-base exempt. |

- Canonical JSON is key-sorted with no insignificant whitespace, so the hash is
  reproducible across runtimes.
- The verify job walks a chain and reports the first `seq` whose recomputed hash
  differs, emitting `audit.chain.verify` and, on failure, `audit.chain_broken`
  (`contracts/types/errors.md` §3). It runs on a schedule and on demand under
  `audit.chain.verify`.
- `sampling.aggregatedCount` and `sampling.windowEnd` are **excluded from the
  hash input**, which is why the view-counter increment (§3) cannot break
  tamper evidence. Everything an investigator relies on is hashed; the
  affordability counter is not.

## 6. Append-only (REQ-AUD-03) and the entity-base exemption

`audit_events` and `audit_chain` are append-only:

- The app role holds `INSERT` and `SELECT` only. No `UPDATE`, no `DELETE`, no
  `TRUNCATE` — enforced by grants, not by code.
- A `BEFORE UPDATE OR DELETE` trigger raises `audit.append_only_violation` even
  for a role that acquires the privilege later.
- The view-counter path (§3) runs as the audit writer role in a function with
  `SECURITY DEFINER`, which is the only grant that may touch an existing row,
  and it may touch only `sampling.aggregatedCount` and `windowEnd`.
- Retention purge and legal hold (REQ-AUD-13) run as a separate maintenance
  role, are themselves audited, and are blocked while the legal-hold flag is
  set (`audit.legal_hold_active`).

Because the table is append-only, it is **exempt from the entity base's
update/delete columns** — all seven, exactly as enumerated in
`contracts/types/entity-base.md` §6 for `audit_events` and `audit_chain`. The
event carries its own actor and timestamp; `updated_*` and `deleted_*` would be
permanently null, and `comment` is already a first-class envelope field. This
file does not add an exemption — §6 of the entity base remains the only place
exemptions are enumerated.

RLS still applies: `audit_events` is tenant-scoped, and its policy is
append-only shaped (`contracts/db/rls-contract.md` §5).

## 7. Change rules after the G3 freeze

**Additive**
- A new event name in a domain's own namespace.
- A new `result` value, a new `source` value, a new `kind`. Readers filter on
  known values and must treat an unknown one as "other", not crash.
- A new optional field on the envelope, excluded from the hash input.
- A new redaction declaration, or tightening an existing one from `hash` to
  `drop`.

**Breaking — needs orchestrator arbitration (REQ-CTR-03)**
- Changing the hash input, in any way. Every existing chain stops verifying.
  A new algorithm is a new chain from a new genesis row, versioned in
  `audit_chain`, with the old chain kept verifiable.
- Renaming an event name, or reusing one with a different meaning.
- Making `diff` required, or widening what may appear inside it.
- Loosening a redaction declaration — that is a data-protection regression and
  the default answer is no.
- Granting the app role `UPDATE` or `DELETE` on `audit_events`.
