# Internationalisation

Every user-visible string in the app, its emails, its PDFs, its error bodies and
its audit summaries comes from a message catalogue. Owned by **A14** (`i18n`):
`packages/i18n/**` and `locales/**`. A14 publishes the `i18n-namespace` registry
and the ICU catalogues; it consumes every domain's key declarations. A14 does not
write another domain's strings and no domain writes into `locales/**` — the
English catalogue is *generated* from the declarations (§3), which is how
fourteen agents add strings in the same minute without touching one file.

## Requirements covered

REQ-I18N-01 … REQ-I18N-08, REQ-CTR-03, REQ-CTR-05, REQ-MAIL-03, REQ-API-10,
REQ-AUD-04, REQ-DOC-04, REQ-TIM-04.

## 1. ICU, and the one thing ICU may not do (REQ-I18N-03)

Messages are ICU MessageFormat, resolved by `next-intl` (version from
`versions/manifest.json`, REQ-VER-02) so Server and Client Components read the
same catalogue.

```
session.list.count =
  {n, plural, =0 {No active sessions} one {# active session} other {# active sessions}}
audit.export.summary =
  {actor} exported {rows, number} rows from {resource} at {at}
```

Plural, `select`, `selectordinal` and `{n, number}` are all used. **ICU date and
time skeletons are banned in catalogues.** `{at, date, short}` would be a second
date formatter, which is exactly the failure mode REQ-TIM-04 exists to prevent
(`spec/time.md` §1). A timestamp arrives as an already-formatted string produced
by `packages/contracts/time`, interpolated as `{at}`. `pnpm lint:i18n` fails on
`, date` or `, time` inside any catalogue value.

## 2. Key naming (REQ-I18N-05)

```
<namespace>.<surface>.<element>[.<variant>]

segments   [a-z0-9-]+, dot separated, 3 to 5 segments
examples   auth.login.submit
           grid.filter.date.preset.7d
           audit.event.rbac-role-update.summary
           mail.invite.subject
```

The key names the **position and role** of the string, never its English text.
`auth.login.enter-your-email` is a rejected key: the copy will change, the key
cannot. Keys are contract members, so they are **additive only** (REQ-CTR-03) —
a message whose *meaning* changes gets a new key and the old one is deprecated
with a removal version. Rewording the same meaning is a catalogue edit and needs
no new key; that distinction is the reviewer's job at CCR time.

## 3. Namespaces, declaration and the collision check

One namespace per domain, and the namespace is the domain's property:

| Namespace | Owner | Namespace | Owner |
|---|---|---|---|
| `auth` | A03 | `audit`, `console` | A13 |
| `rbac`, `tenant` | A04 | `mail`, `notify` | A12 |
| `nav`, `shell`, `settings` | A05 | `api`, `apikey` | A11 |
| `theme` | A06 | `canonical`, `quarantine` | A10 |
| `grid` | A07 | `help`, `glossary` | A16 |
| `pwa` | A09 | `common`, `error`, `time`, `entity` | A02 |

A domain declares its namespace **and its English source strings** in its own
package:

```ts
// packages/auth/contract.declaration.ts (A03)
i18nNamespace: "auth",
messages: {
  "auth.login.submit": "Sign in",
  "auth.login.mfa.prompt": "Enter the 6-digit code from your authenticator",
},
```

A14 generates `locales/en/auth.json` from the declarations and hand-maintains
`locales/sv/auth.json`. English lives next to the code that renders it; the
translation lives in the catalogue. Assembly fails on a duplicate namespace or a
duplicate key and names both claimants (`contracts/README.md` §3), and on a key
whose prefix is not the declaring agent's namespace — the check that stops A07
from writing an `auth.*` string.

`common.*` is A02's and is for genuinely shared words: `Save`, `Cancel`,
`Delete`, `Yes`, `No`, `Loading`. It is not a dumping ground; a string used by
one domain belongs to that domain even if it is short.

## 4. Resolution order (REQ-I18N-04)

```
user preference (user_preferences.locale, A05)
  → tenant default (tenants.default_locale, A04)
    → Accept-Language, q-weighted, BCP-47 lookup match
      → system default: en
```

Resolved once per request in middleware, put on the request context, and read
from there by RSC, Server Actions, route handlers and the mail renderer. There is
**no locale segment in the URL**: the app is authenticated, the locale is a
preference, and a `/sv/...` prefix would make every link locale-dependent and
every bookmark wrong after a preference change. `?lang=<tag>` overrides one
render for support purposes, never persists, and is recorded on the read audit
event so a screenshot taken in another language is explainable.

A locale is added by dropping `locales/<tag>/*.json` in place and adding the tag
to the registry — data, not code (REQ-I18N-06). `en` and `sv` ship.

## 5. What is translated beyond the UI (REQ-I18N-01)

| Surface | Namespace | Locale used | Notes |
|---|---|---|---|
| App UI | per domain | the request's | |
| Emails | `mail` | the **recipient's**, not the sender's | Subject, HTML body and the plain-text alternative, all three (REQ-MAIL-03) |
| Push notifications | `notify` | the recipient's | Rendered at send time; the payload still carries no content (REQ-PWA-04) |
| PDFs | `help`, `compliance` | the requester's | Export headers and compliance documents |
| Audit summaries | `audit` | the **reader's** | `audit.event.<name>.summary` is rendered at read time from the stored machine fields. A rendered sentence is never stored — a row written in Swedish and read by an English operator must read in English |
| Audit reason templates | `audit` | the actor's, at write time | The operator's free-text reason is stored verbatim and never translated |
| Error bodies | `error` | the request's | `title` and `detail` are localised; `type`, `code` and `status` never are (`spec/api.md` §4) |
| Validation messages | `error` | the request's | Field paths are identifiers and stay as they are |
| Help topics | `help` | the reader's | One file per topic per locale (REQ-DOC-04) |
| Grid exports | the grid's | the requester's | Column headers localised; data values are data |
| Logs, syslog, debug console | — | **not translated** | Operator- and machine-facing English. A log line grepped in one language and forwarded in another is unusable (REQ-AUD-07) |

## 6. The hardcoded-literal check (REQ-I18N-02)

`pnpm lint:i18n` fails CI on a user-visible literal in a rendered path.

Flagged: JSX text nodes; the props `title`, `label`, `placeholder`,
`aria-label`, `aria-description`, `alt`, `summary`, `caption`; string arguments
to `toast.*`, `notify.*` and `confirm()`; `throw new Error` in a path whose
message reaches a response body; email subject strings; `<option>` labels.

Not flagged, and why each is a genuine false positive rather than an excuse:

| Not flagged | Reason |
|---|---|
| Permission strings, table names, event names, error codes, route paths | Identifiers. Translating one breaks a lookup |
| `data-*`, `className`, `id`, `name`, `type`, `href` | Not rendered as prose |
| Strings that are only digits, punctuation or a single symbol | `"—"`, `":"`, `"/"` carry no language |
| Test files, fixtures, seeds, mockups under `mockups/` | Not a rendered production path |
| Log messages, syslog structured data, console event fields | Not translated by decision (§5) |
| Technical values inside `<code>` / `<pre>` | Code is not prose |
| A catalogue file itself | It is the catalogue |

Anything else needs an inline `// i18n-exempt: <reason>` — the reason is
mandatory and the rule fails on a bare pragma. Exemptions are counted in the
coverage report, so a build that grows them is visible rather than quiet.

## 7. Coverage (REQ-I18N-07)

`pnpm i18n:coverage` prints and writes `build/i18n-coverage.json`:

| Column | Meaning |
|---|---|
| keys | Declared in the namespace |
| translated | Present and non-empty in the target locale |
| missing | Declared, absent in the target locale |
| stale | Present, but the `en` source hash recorded in the target catalogue's `@meta` no longer matches — the English changed and the translation did not |
| unused | In the catalogue, referenced nowhere in the source |
| exempt | `i18n-exempt` pragmas in that domain's files |

`sv` below 100% on any namespace fails the gate, with the missing keys listed
per owning agent so the finding routes without triage. `stale` is a first-class
column because a silently outdated translation is worse than a missing one: the
missing key is visible in dev and falls back in prod, while a stale one reads as
correct and is wrong.

## 8. Fallback: loud in development, silent in production

| Environment | Behaviour on a missing key |
|---|---|
| Development | Renders `⟦auth.login.submit⟧` in the `--destructive` colour, logs `error` with the key and the component, and fails `pnpm test:e2e` if any marker appears in a screenshot |
| Production | Falls back to `en` silently in the UI, emits one `warn` log per key per process with a counter, and never renders the key or an empty string |

A raw key on a user's screen is a bug report from the user instead of from CI.
An empty string is worse: it looks like the feature is missing.

## 9. RTL readiness (REQ-I18N-08)

No RTL locale ships, and the layout is still direction-agnostic, because
retrofitting direction after a hundred components exist is a rewrite.

- Logical properties only: `ms-*`/`me-*`, `ps-*`/`pe-*`, `start-*`/`end-*`,
  `text-start`/`text-end`, `border-s`/`border-e`, `rounded-s`/`rounded-e`.
- Banned in `apps/**` and `packages/**`: `ml-*`, `mr-*`, `pl-*`, `pr-*`,
  `left-*`, `right-*`, `text-left`, `text-right`, `border-l`, `border-r`.
  `pnpm lint:tokens` carries the deny list alongside A06's colour rules.
- `<html dir>` is set from the locale registry's `direction` field, server-side,
  in the same pass that sets the theme class (`spec/theming.md` §4).
- Direction-encoding icons — chevrons, arrows, indent controls — carry
  `rtl:-scale-x-100`. A clock or a checkmark does not.
- A pseudo-locale `en-XA` (mirrored, direction `rtl`) is available in development
  and screenshotted at 390/834/1440 in the visual suite, so the readiness claim
  is tested rather than asserted.

## Decisions and defaults

| Decision | Choice | Why | Intake-overridable? |
|---|---|---|---|
| Library | `next-intl`, ICU | Native ICU, one catalogue for RSC and client | No |
| ICU date/time skeletons | Banned in catalogues | A second formatter breaks REQ-TIM-04 | No |
| Key shape | `<namespace>.<surface>.<element>[.<variant>]`, 3–5 segments | Position, not text | No |
| Keys as contract members | Additive only; new meaning, new key | REQ-CTR-03 | No |
| English source location | In the domain's declaration; `locales/en/**` generated | Fourteen agents, one file, otherwise | No |
| Swedish catalogues | Hand-maintained by A14 under `locales/sv/**` | Translation is not a generated artefact | No |
| Locale in the URL | No prefix; a non-persisting `?lang=` for support | Bookmarks must survive a preference change | Yes |
| Resolution order | user → tenant → `Accept-Language` → `en` | REQ-I18N-04 | No |
| Shipped locales | `en`, `sv`; `en` is the base | REQ-I18N-06 | Yes, add only |
| Logs and console | Not translated | Operator-facing English is greppable | No |
| Stored audit text | Machine fields stored; summary rendered per reader | A stored sentence has one language forever | No |
| Missing key in prod | Silent `en` fallback + one `warn` per key | Never show a key or a blank | No |
| Exemption pragma | `// i18n-exempt: <reason>`, reason mandatory | A bare pragma is an unreviewed decision | No |
| RTL | Logical properties from day one, `en-XA` pseudo-locale | A retrofit is a rewrite | No |

## How this is verified

- `pnpm lint:i18n` — §6 in full, plus no `, date`/`, time` in any catalogue
  value, plus no bare `i18n-exempt` pragma.
- `pnpm i18n:coverage` — §7; `sv` at 100% on every namespace, zero `stale`,
  zero `unused`. Gate-blocking.
- `pnpm test:unit` — `tests/unit/i18n/**`: plural forms for `en` and `sv` at
  n = 0, 1, 2 and 21; resolution order over the full matrix of user, tenant and
  `Accept-Language` inputs including an unmatchable header; `?lang=` does not
  persist.
- `pnpm test:e2e` — `tests/e2e/i18n/**`: the app in `sv` end to end, asserting
  no `⟦key⟧` marker appears in any screenshot; an email rendered in the
  recipient's locale while the actor's session is the other one; an audit row
  written in `sv` read back in `en`.
- `pnpm test:visual` — `tests/visual/i18n.spec.ts`: `en`, `sv` and `en-XA` at
  390/834/1440; Swedish is the longest-string locale here and must not clip or
  overflow any surface budget (`spec/screenspace.md` §4).
- `pnpm test:contract` — `packages/contracts/tests/i18n.spec.ts`: no duplicate
  namespace or key, every declared key is prefixed with its owner's namespace,
  every `NavEntry.i18nKey` and help topic key resolves in both locales
  (REQ-CTR-10).
