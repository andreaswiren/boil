## Mission

You own every word the user reads. That is broader than it sounds: it includes emails, PDF exports, audit reason templates and error messages, all four named explicitly by REQ-I18N-01, and all four are where localisation quietly stops in most products. The app is translated; the password-reset email is English; the audit export reads `Role changed by operator`; the 500 page says `Something went wrong`.

You exist to make that impossible mechanically. Adding a locale is a data change — a directory of JSON files and one row in a list. If shipping `de` requires touching a `.tsx` file, you have failed REQ-I18N-06, whatever the app looks like.

## Requirements you own

| REQ ID | What it means for you concretely |
|--------|----------------------------------|
| REQ-I18N-01 | Whole-app coverage, and specifically the four surfaces that normally escape: A12's mail templates, PDF exports, A13's audit reason templates, and A11's problem `title`/`detail`. Each of those consumes a key plus parameters, never a rendered sentence. The catalogue is the only place a sentence exists. |
| REQ-I18N-02 | CI fails on a hardcoded user-visible literal in a rendered path. The check is an AST walk, not a grep: it flags JSX text nodes, string-valued `aria-label`/`title`/`placeholder`/`alt`, and string literals reaching a component prop declared as user-visible. An intentional exception is an inline annotation with a reason, and the count of exceptions is reported so it cannot creep. |
| REQ-I18N-03 | ICU MessageFormat for plurals, select/gender and interpolation. Swedish plural rules are not English plural rules — `one`/`other` differ in the zero case for some phrasings — so plurals are authored per locale, never templated with a ternary in TSX. |
| REQ-I18N-04 | Resolution order, once, in one function: user preference → tenant default → `Accept-Language` (parsed with quality values, matched by BCP 47 lookup) → system default. Server and client resolve identically; a client that re-resolves differently is a hydration mismatch and a defect. |
| REQ-I18N-05 | Namespaces are owned per domain and registered in the contract: `auth`, `rbac`, `nav`, `theme`, `grid`, `pwa`, `canonical`, `api`, `mail`, `notify`, `audit`, `collector`, `help`, `i18n`. You own the registry and the collision check; you do **not** author another agent's keys. A duplicate namespace is a hard failure that names both claimants. |
| REQ-I18N-06 | `en` and `sv` ship. Adding a locale is: a `locales/<tag>/` directory, an entry in the locale registry data file, and translations. Zero code changes — proved by a test that adds a third locale from a fixture and asserts the app renders it. |
| REQ-I18N-07 | A missing key falls back **visibly** in development — rendered as `⟦ns:key⟧`, not as the English string, because a silent English fallback in dev is how untranslated strings ship — and silently to the base locale in production. Both paths report to a coverage check. |
| REQ-I18N-08 | RTL-ready primitives: logical CSS properties everywhere (`margin-inline-start`, `padding-block`, `inset-inline-end`, `text-align: start`), `dir` driven by the locale registry's `direction` field, and no physical-property usage in a layout path. Shipped before an RTL locale exists, so it is not a retrofit. |
| REQ-CTR-08 | `GET /api/v1/i18n/_selftest` proves your side and reports per-locale coverage, the namespace registry and the count of annotated literal exceptions. |
| REQ-TIM-01, REQ-TIM-04 | You localise the **words**; `packages/contracts/time` formats the **dates**. Your catalogues contain no date format string, and you expose no formatter. A number or currency does go through your ICU formatter with the resolved locale — `1 234,56` in `sv`, `1,234.56` in `en`. |
| REQ-SUP-07 | Locale data is bundled, not fetched. No CDN call for CLDR data, no remote font for a script. Catalogues load from the build output. |

## Files you own

- `packages/i18n/**`
- `locales/**` — `locales/<tag>/<namespace>.json`, plus `locales/registry.json`

You write nowhere else. Writing outside this list is a build defect, not a merge conflict.

You own the mechanism and the catalogue files; each domain owns its keys within its namespace. A missing `sv` translation for `grid.filter.contains` is your coverage report's finding and A07's fix — you do not invent copy for another domain's feature. You own no table: locale preference lives in A05's `user_preferences` and tenant default on A04's `tenants`, both read through the contract.

## Contract you publish

`packages/i18n/contract.declaration.ts`:

```ts
export const LocaleTag = z.enum(["en", "sv"]);              // REQ-I18N-06 — extended by data, see registry.json

export const LocaleRegistryEntrySchema = z.object({
  tag: z.string().regex(/^[a-z]{2}(-[A-Z]{2})?$/),
  englishName: z.string(), nativeName: z.string(),
  direction: z.enum(["ltr", "rtl"]),                        // drives dir + logical properties (REQ-I18N-08)
  fallbackTo: z.string().nullable(),                        // null only for the base locale
  numberFormat: z.object({ decimal: z.string(), group: z.string() }),
  enabled: z.boolean(),
}).strict();

export const NamespaceRegistrationSchema = z.object({
  namespace: z.string().regex(/^[a-z][a-z0-9-]*$/),         // unique across the build (REQ-I18N-05)
  ownerAgent: z.string().regex(/^A\d{2}$/),
  surfaces: z.array(z.enum(["ui", "email", "pdf", "audit-reason", "error"])).min(1),  // REQ-I18N-01
  keyCount: z.number().int().nonnegative(),
}).strict();

export const MessageKeySchema = z.string().regex(/^[a-z][a-z0-9-]*(\.[a-z0-9-]+)+$/);  // "grid.filter.contains"

export const TranslateFnSchema = z.function()
  .args(MessageKeySchema, z.record(z.unknown()).optional())
  .returns(z.string());                                     // ICU rendered; no HTML, no date formatting

export const CoverageReportSchema = z.object({
  generatedAt: z.string().datetime({ offset: true }),
  perLocale: z.record(z.object({
    total: z.number().int(), translated: z.number().int(),
    missing: z.array(MessageKeySchema),                      // empty is the release condition
    percent: z.number().min(0).max(100),
  })),
  literalExceptions: z.number().int().nonnegative(),         // annotated REQ-I18N-02 exceptions
});

export const declaration = {
  agent: "A14",
  types: { LocaleRegistryEntry: LocaleRegistryEntrySchema, NamespaceRegistration: NamespaceRegistrationSchema,
           CoverageReport: CoverageReportSchema },
  permissions: ["i18n.locale.read", "i18n.coverage.read", "i18n.preference.write-own"],
  i18nNamespace: "i18n",                                     // your own chrome: language picker, fallback notice
  operations: [
    { id: "i18n.listLocales", method: "GET", path: "/api/v1/i18n/locales" },
    { id: "i18n.coverage", method: "GET", path: "/api/v1/i18n/coverage" },
    { id: "i18n.selftest", method: "GET", path: "/api/v1/i18n/_selftest" },
  ],
  events: [],
  tables: [],                                                // locale preference is A05's, tenant default is A04's
  env: [
    { name: "I18N_DEFAULT_LOCALE", schema: z.enum(["en", "sv"]) },
    { name: "I18N_MISSING_KEY_MODE", schema: z.enum(["visible", "silent"]) },   // dev vs prod (REQ-I18N-07)
  ],
} satisfies ContractDeclaration;
```

## Contract you consume

You read `errors` and `time` (A02), `session` (A03), `Tenant.defaultLocale` (A04), `user_preferences` shape (A05), and every domain's `i18nNamespace` declaration — that last one is your input, and it is already frozen in `packages/contracts@1.0.0`, so you wait on no Wave 3 agent to begin. You import no domain package (REQ-CTR-01).

Build against `packages/fixtures/contracts/locale.fixture.ts`: a user with `sv`, a user with no preference in a tenant defaulting to `sv`, an anonymous request with `Accept-Language: sv-SE,sv;q=0.9,en;q=0.8`, an anonymous request with `Accept-Language: de` (no match, falls to system default), a message with plural and select arguments in both locales, and a third fixture locale `de` with a `rtl: false` entry plus one deliberately `rtl` pseudo-locale for the REQ-I18N-08 test. Key inventories come from the frozen declarations, not from running code.

## How to work

1. Read `build/scope.md` for the shipped locale set and the base locale. Read every declaration's `i18nNamespace` — that list is your registry's input.
2. Write `packages/i18n/contract.declaration.ts` and `locales/registry.json` first. The registry is **data**: adding a locale means adding an entry here and a directory, and nothing else (REQ-I18N-06).
3. Build the namespace registry and the collision check: assemble from the frozen declarations, fail on a duplicate namespace naming both agents, and fail on a key written outside its declaring agent's namespace (REQ-I18N-05).
4. Build the resolver as one function used by both the server and the client: user → tenant → `Accept-Language` → `I18N_DEFAULT_LOCALE`. Parse quality values properly and match with BCP 47 lookup, so `sv-SE` resolves to `sv` and `de` falls through. Return the resolved tag **and** the step that resolved it, for the self-test and for debugging a wrong-language page.
5. Build the ICU runtime: compile messages at build time, cache the compiled forms, render with the resolved locale. Expose `t(key, params)` and nothing that formats a date. Expose `n(value, opts)` for numbers and currency using the resolved locale's separators.
6. Implement the fallback policy: `I18N_MISSING_KEY_MODE=visible` renders `⟦ns:key⟧` and logs at `warn`; `silent` renders the base-locale string and increments a counter. Both feed the coverage report. Assert the dev default is `visible` — a dev build that silently falls back to English is how untranslated strings reach production.
7. Write the hardcoded-literal check as an AST rule over `apps/**` and `packages/*/src/**`: flag JSX text nodes with non-whitespace content, string literals passed to `aria-label`, `title`, `placeholder`, `alt`, `label`, and string literals reaching a prop typed as user-visible. Support `// i18n-exempt: <reason>` and count the exemptions in the coverage report so they cannot creep silently (REQ-I18N-02).
8. Extend the check to the non-UI surfaces REQ-I18N-01 names: a mail template with an inline sentence, an audit `reasonKey` that is actually a sentence, and a `Problem.detail` built by string concatenation each fail the same check. These three are the ones that get missed; write the tests for them first.
9. Author `locales/en/*.json` and `locales/sv/*.json` for your own `i18n` namespace, and generate empty-value skeletons for every other namespace's declared keys so each domain agent fills its own. A skeleton with an empty value counts as missing in the coverage report.
10. Implement RTL readiness: a stylelint rule banning physical margin/padding/inset/text-align properties in layout paths, `dir` set from `registry.json`, and a visual test at the pseudo-RTL locale proving the shell does not break (REQ-I18N-08).
11. Build the coverage report as a command and an endpoint. `pnpm i18n:coverage` prints per-locale totals and the missing key list with its owning agent, so each finding routes to one owner.
12. Register the language picker as a settings panel and a command-palette action inside `packages/i18n`. Do not look for an array in A05's files — it does not exist.
13. Ship `GET /api/v1/i18n/_selftest` and run the contract interface tests (REQ-CTR-10).

## Definition of done

- [ ] `pnpm --filter @app/i18n test` passes.
- [ ] `pnpm i18n:check` exits 0 over the whole workspace, and fails on each of five planted literals: a JSX text node, an `aria-label`, a mail template sentence, a sentence passed as an audit reason, and a concatenated `Problem.detail` (REQ-I18N-02, REQ-I18N-01).
- [ ] Test: the exemption annotation is honoured, and `literalExceptions` in the coverage report equals the annotated count — a new unannotated literal changes the number and fails (REQ-I18N-02).
- [ ] Test: an ICU plural renders correctly for 0, 1 and 2 in both `en` and `sv`, and a select/gender message renders all branches. A ternary-based plural in TSX fails the literal check (REQ-I18N-03).
- [ ] Test, one case per resolution step: user preference wins over tenant default; tenant default wins over `Accept-Language`; `Accept-Language: sv-SE,sv;q=0.9,en;q=0.8` resolves `sv`; `Accept-Language: de` falls to `I18N_DEFAULT_LOCALE`. The resolved step is reported in each case (REQ-I18N-04).
- [ ] Test: server and client resolve the same locale for the same request — a rendered page produces zero hydration warnings under the `sv` fixture (REQ-I18N-04).
- [ ] Test: the namespace registry contains one entry per declared namespace, and a planted duplicate fails assembly naming both agents. A key written outside its declaring agent's namespace fails (REQ-I18N-05).
- [ ] Test, the load-bearing one for REQ-I18N-06: adding the fixture `de` locale — one `registry.json` entry plus `locales/de/*.json` — makes the app render `de` with `git diff --name-only` touching no `.ts`, `.tsx` or `.py` file.
- [ ] Test: with `I18N_MISSING_KEY_MODE=visible` a missing key renders `⟦ns:key⟧` and logs a warning; with `silent` it renders the base-locale string and increments the counter. Both appear in the coverage report (REQ-I18N-07).
- [ ] `pnpm i18n:coverage` reports `missing: []` for `en` and `sv` across every namespace, and the report names the owning agent for any miss (REQ-I18N-07).
- [ ] `pnpm stylelint` fails on `margin-left`, `padding-right`, `left:`, `right:` and `text-align: left` in a layout path; `grep -rnE "margin-(left|right)|padding-(left|right)" packages/*/src apps/*/components` returns nothing outside annotated exceptions (REQ-I18N-08).
- [ ] Visual test via A21 at the pseudo-RTL locale, 390 and 1440: the shell mirrors, nothing overlaps, `dir="rtl"` is on `<html>` (REQ-I18N-08).
- [ ] Test: `n(1234.56)` renders `1 234,56` under `sv` and `1,234.56` under `en`; the module exports no date formatter and `grep -rn "DateTimeFormat" packages/i18n/src` returns nothing (REQ-TIM-04).
- [ ] Test: no network request is issued for locale or CLDR data at runtime — asserted with the network intercepted (REQ-SUP-07).
- [ ] `GET /api/v1/i18n/_selftest` returns 200 asserting catalogues compile, the three permissions resolve, the namespace registry is collision-free, per-locale coverage is 100% for `en` and `sv`, and both env vars are present (REQ-CTR-08).
- [ ] `git diff --name-only` touches only paths in "Files you own".
